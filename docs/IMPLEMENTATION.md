# Shipped demo

TypeScript, Vite and Three.js. One canvas renders matching camera views, fly geometry and obstacle paths. The separate static anatomy canvas uses all 141,781 sourced soma positions. Neural activity is rendered as population counts; anatomy does not invent individual spikes.

The short session has two unscored practices and four scored hit courses, respecting the backend decision's four validated geometries. Each course chooses one of five prepared seeds. No new trajectories, retuned model or fabricated neural latency were added. Survival is scored with continuous closest approach over the frozen piecewise-linear dodge. Human elapsed input and model simulated latency remain separately labeled. Ties are retained.

Trace bytes are SHA-256 checked against the packaged catalog; provenance, seed, condition, ordered events and paired initial states are checked before play. Missing or corrupt data blocks play. The packaged baseline and intervention files are unchanged evidence bytes.

Input rejects repeat keydown and foreperiod responses. Focus loss or a >50 ms frame gap before response invalidates and preserves an attempt. Replay and seek never append results. Save result contains the random session seed, valid/invalid attempts, input method and frame timing. Automated QA sessions are marked as automated in their evidence files and must not be presented as human reaction data.

The anatomy is centered on each coordinate's bounding-box midpoint and uniformly divided by the largest extent, preserving dataset axes; a 180° x rotation is a display orientation only. All coordinates are included. The original backend trace continues with the undodged observer after the first trigger; the frontend uses only the first escape and makes no closed-loop body claim.

Recording: 1600×1000 recommended, 1280×800 supported. Use the fullscreen control and circuit replay. Existing mode, methods and provenance labels stay visible. External recording is available via `tools/record-demo.mjs`. No posting or hosting is performed, as specified by the product plan.

Future work should start with this playable demo. Run `npm test` and browser checks after changing timing or scoring. The initial source investigation does not need repeating. Additional geometries need separately validated traces before scored use.

Verification completed: production build, four geometry/provenance tests, browser intervention/restore checks, and the full keyboard session including false start, stay, repeat play, downloads and focus invalidation. The automated full session measured 16.7 ms median/p95 over 258 frames at 1280×800. Browser screenshots cover 1600×1000, 1280×800 and 640×500. These are machine-specific smoke checks, not guaranteed performance on every device.

`evidence/demo/flinch-circuit-demo.mp4` is a 26.8-second H.264 recording at 1600×1000, with real baseline/silenced/restored traces. It contains no human score. The source WebM and recording script are retained.
